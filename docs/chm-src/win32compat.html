Win9x ANSI / Unicode Backport (U-1)

Problem

Stock Lazarus LCL uses W-variant (Unicode) Windows APIs that don't exist on Win95/98/ME. 46 W-calls cause crashes on Win9x.

Solution

win32compat.pas (196 lines) provides A/W dispatch:

  • Default (no define): ANSI APIs — Win9x/ME safe
  • -dUNICODE: Wide APIs — NT/2K/XP+
  • Runtime UnicodeEnabledOS checks preserved in LCL

Modified Files

win32callback.inc, win32object.inc, win32wscontrols.pp, win32proc.pp, win32listsl.inc, win32wscomctrls.pp, win32wsstdctrls.pp, win32memostrings.inc, win32winapi.inc, win32wschecklst.pp, win32wsspin.pp, win32wsdialogs.pp, win32int.pp, multimon.pp

U-2 (Infrastructure)

win32compat.pas IS the infrastructure. {$IFDEF UNICODE} selects W-variants.

U-3 (Unicode Build)

Compile with -dUNICODE for Wide APIs on NT+.

U-4 (Linux UTF-8)

Pass-through. No conversion needed. LazUtils has 10,427 lines of UTF-8 support.
